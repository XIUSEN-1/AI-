# AI 能力罗盘 · 设计文档（Spec）

日期：2026-09-12 · 状态：待用户审阅

## 1. 背景与目标

- **赛事**：2026"数字马力杯"第十三届浙江省大学生服务外包创新应用大赛，A01「AI 能力测评智能体」（数字马力命题）。
- **一句话定位**：面向高校学员的 AI 能力自适应测评智能体——通过对话式交互、实操任务考核与多维评估模型，完成 AI 能力的自动化测评与精准画像，并输出个性化学习路径。
- **硬性交付物**（对应赛题任务清单）：
  1. 能力维度定义 + 题库（≥5 维度，每维度 ≥10 基础题 + 5 进阶题）
  2. 可运行的自适应测评系统（含前端交互）
  3. 自动评分与报告生成（雷达图 + 文字建议）
  4. 演示视频或可访问测试环境（本项目两者都做）
  5. 未来发展文档（与"AI 智能·教学辅具"数据打通、学习路径推荐）
- **评分权重映射**（设计决策以此为纲）：
  | 评分维度 | 权重 | 本项目对应 |
  | --- | --- | --- |
  | 能力维度定义合理性 | 25% | 六维模型 + L1-L5 行为锚定分级 |
  | 自适应机制有效性 | 25% | 分维度能力估计引擎 + 可解释出题 |
  | 自动评分准确性 | 20% | LLM 判题 + 校准实验与一致性数据 |
  | 系统演示效果 | 20% | 公网部署 + 报告可读性 + 三模式完整闭环 |
  | 创新性与可扩展性 | 10% | 成长追踪、班级画像、校企衔接设计 |

## 2. 已定案约束

- **大模型**：DeepSeek（OpenAI 兼容 API），接入层抽象为 provider 可切换（后续接入 GLM / 蚂蚁百宝箱零改动）。
- **部署**：秒悟 Meoo → 阿里云，公网可访问测试环境 + 演示录屏双保险。
- **技术栈**：前端 React 18 + TS + Vite + Tailwind + shadcn/ui + Recharts；后端 Python FastAPI + SQLite(WAL) + SQLAlchemy 2.0；单容器（FastAPI 托管前端构建产物）。
- **团队与排期**：由 AI 代理全栈开发，用户验收；按 M1→M2→M3 里程碑推进（见 §11）。

## 3. 能力模型（对应权重 25%）

### 3.1 六维能力

| # | 维度 | 定义 | 典型考察行为 |
| --- | --- | --- | --- |
| D1 | AI 基础认知 | 对 AI 基本概念、模型特点、能力边界的理解 | 区分 LLM 与搜索引擎；知道模型幻觉成因；了解训练/微调概念 |
| D2 | 提示词工程 | 设计有效指令以驱动 AI 产出 | 指令清晰度、任务拆解、上下文编排、少样本示例 |
| D3 | AI 工具使用 | 选用合适的 AI 工具完成任务 | 文本/图像/代码生成、办公插件、数据分析工具的选型与使用 |
| D4 | AI 结果评估与优化 | 甄别与改进 AI 产出 | 识别事实错误、偏见、幻觉；提出改进指令 |
| D5 | 人机协同解决问题 | 借助 AI 分步完成复杂任务 | 任务规划、人机分工、迭代修正、结果整合 |
| D6 | AI 伦理与合规 | 负责任地使用 AI | 隐私保护、版权意识、学术诚信、生成内容标注 |

### 3.2 五级等级（每维度独立定级）

统一等级语义 + 每维度行为锚定描述（完整锚定表随题库交付，存 `docs/competency-model.md`）：

| 等级 | 名称 | 通用语义 |
| --- | --- | --- |
| L1 | 初识 | 了解基本概念，能在引导下完成简单操作 |
| L2 | 会用 | 能独立完成常见场景的 AI 辅助任务 |
| L3 | 熟练 | 能拆解任务、写出高质量提示词、甄别产出质量 |
| L4 | 精通 | 能编排多轮/多工具协同流程，优化迭代产出 |
| L5 | 专家 | 能设计系统性人机协作方案，指导他人，理解技术边界与风险 |

## 4. 题库设计

- **规模**：6 维度 ×（10 基础 + 5 进阶）= **90 题**，存 `seeds/questions/*.json`（版本化，导入 SQLite）。
- **题型**：
  - 基础题（难度 1-3）：单选、多选、判断，规则引擎判分。
  - 进阶题（难度 4-5）：情境开放题（对话式考核，LLM 判题）；每维度 ≥1 道实操任务题。
- **多模态**：图像鉴别类题目采用**预置对比素材**（AI 生成图 vs 实拍/真实截图，素材入仓 `seeds/assets/`），不依赖图像生成 API；代码类题目以文本代码块呈现。
- **元数据**：`dimension, difficulty(1-5), type, tags[], est_seconds, answer(客观题), rubric(开放题), version, status(draft/published)`。
- **Rubric 规范**：每道开放题附 0-4 分锚定评分点（每分值一行为为描述）+ 评分要点清单，供 LLM 判题与人工校准共用。

## 5. 测评流程与自适应引擎（对应权重 25%）

### 5.1 流程

```
登录(学员) → 开始测评
  → 阶段一 摸底：6 题（每维度 1 题，难度≈3）
  → 阶段二 分维度自适应客观题（每维度 4~6 题，动态难度）
  → 阶段三 对话式测评（抽取 2~3 个维度的进阶情境题，LLM 考官多轮追问）
  → 阶段四 实操任务（1~2 个综合任务：内嵌真实 DeepSeek 对话窗口，学员现场拆解、
      写提示词、甄别并整合产出，全程留痕提交）
  → 评分汇总 → 报告生成
```

- 总时长目标 ≤30 分钟；每阶段可暂停续答（session 持久化）。
- 速测模式（可选）：仅阶段一 + 二，约 10 分钟，牺牲 D5 精度。

### 5.2 自适应算法

- 每维度独立能力估计 `θ_d ∈ [1.0, 5.0]`，初始 3.0。
- 更新规则（Elo 期望式，系数以引擎单测校准为准）：
  - 期望掌握度 `E = 1 / (1 + exp(-(θ - d)))`（θ 与题目难度 d 同尺度）。
  - 更新：`θ += K · (result - E)`；`K = 0.8 / (1 + 0.25·n_d)` 随该维度答题数衰减。
  - `result`：客观题答对 1 / 答错 0；**开放题/对话/实操由 0-4 分折算为 `score/4`，天然支持部分掌握**。
  - 用时信号：正确但用时 > 2×预估 → 该次更新量 ×0.7（记录进报告，不直接扣分）。
- 选题规则：难度 = `clamp(round(θ_d), 1, 5)`，取该维度未见题目；同档位不足时就近取。
- 停止规则（满足其一）：连续 2 对或 2 错；答题数达 6；能力估计标准误收敛（近 3 次更新幅度 < 0.15）。
- **可解释性**：作答界面实时显示当前 θ 轨迹迷你图与出题理由（"你在提示词工程维度估计 L3，本题验证 L3-L4 边界"）——演示时的核心亮点。

## 6. 自动评分（对应权重 20%）

### 6.1 判题管线

- **客观题**：规则引擎（单选/判断精确匹配，多选集合匹配）。
- **开放题/对话式/实操**：LLM-as-judge（DeepSeek，temperature=0）
  - 输入：题目 + 锚定 rubric + 学员作答（对话式含学员侧全部 prompt）
  - 输出（pydantic 强校验 JSON）：`{score: 0-4, hits: [命中的评分点], strengths: [], gaps: [], rationale: 中文评分理由}`
  - **校验机制**：schema 解析失败重试 ≤2 次 → 仍失败则降级关键词覆盖度评分并进入人工复核队列。
  - **一致性机制**：temperature=0 双跑；分差 >1 → 第三跑取中位；仍 >1 → 标记复核。
- **实操任务双通道评分**：产物质量（任务 rubric）+ 过程质量（学员 prompt 的清晰度/拆解性/迭代甄别行为，独立量表）。

### 6.2 准确性验证（提交材料的数据支撑）

- 构建校准集：50 份开放题作答样本（测评系统内采集 + 预生成）。
- 人工标注评分（记录标注规程），计算 LLM 评分与人工的 Pearson/Spearman 相关系数与加权 Kappa。
- 产出《评分准确性验证报告》纳入提交材料。

## 7. 报告与可视化

- **个人报告**：六维雷达图 + 总等级徽章 + 逐题回显（含每题评分理由，可解释性）+ 优势/短板文字分析 + 个性化学习路径（LLM 生成 + 模板兜底 + 推荐练习）+ 历次测评成长趋势折线 + "AI 使用健康度"建议（防依赖伦理设计）。
- **教师看板**：班级聚合雷达、维度均分排名、共性短板 TOP3、学员成长曲线、CSV 导出。
- **图表库**：Recharts。

## 8. 系统架构

### 8.1 结构

```
ai-compass/
├── web/        # React SPA（答题/对话/实操/报告/教师看板/管理后台）
├── api/        # FastAPI（路由 + 引擎 + 判题 + 报告 + 认证）
│   └── app/
│       ├── main.py            # 入口，托管 web 静态产物
│       ├── engine/            # 自适应引擎（纯逻辑，TDD）
│       ├── judge/             # LLM 判题管线 + schema 校验 + 降级
│       ├── llm/               # provider 抽象（OpenAI 兼容 → DeepSeek/…）
│       ├── report/            # 报告生成
│       └── api/               # 路由：auth/sessions/chat/practical/reports/teacher/admin
├── seeds/      # 题库 JSON + 图像素材（版本化）
└── docs/       # 设计文档 + 提交材料
```

### 8.2 认证与角色

- 学员：姓名/学号 + 班级邀请码自助注册（数据最小化，不收手机号）。
- 教师：账密（创建班级、发放邀请码、看板）。
- 管理员：账密（题库 CRUD、复核队列、批次管理）。JWT 轻认证。

### 8.3 数据模型（核心表）

`users, classes, questions, sessions(测评会话), session_answers(作答+θ快照+judge原始输出), practical_logs(实操对话留痕+产物), reports(维度得分+等级+建议), review_queue(人工复核)`

### 8.4 关键 API 面

- `POST /api/auth/*`；`POST /api/sessions`（开始）；
- `POST /api/sessions/{id}/answer`（判分 + 返回下一题与 θ 轨迹）；
- `POST /api/sessions/{id}/chat`（对话式测评，SSE 流式）；
- `POST /api/practical/{id}/chat`（实操窗口，代理 DeepSeek 并留痕）；
- `POST /api/sessions/{id}/finish` → `GET /api/reports/{id}`；
- 教师：`GET /api/teacher/classes/{id}/analytics` 等；管理：`/api/admin/questions` CRUD。

## 9. 伦理与隐私（赛题明文鼓励，创新分点）

1. **数据最小化与脱敏**：仅收集姓名/学号/作答数据；教师端仅展示聚合统计；日志不落完整对话 PII。
2. **可解释与可申诉**：每个分数附评分理由；学员可对单题发起复核（进 review_queue）。
3. **防依赖设计**：报告含"AI 使用健康度"建议；实操任务要求学员标注 AI 贡献比例。
4. **偏见控制**：rubric 行为锚定、双跑一致性、人工抽检复核三重机制。

## 10. 技术选型说明（提交材料底稿）

| 选型 | 理由 |
| --- | --- |
| FastAPI | async 原生适配 LLM 高 IO 与 SSE 流式；pydantic 强校验判题 JSON；pytest 生态；赛后可平滑扩展 IRT 等心理测量库 |
| SQLite(WAL) | 单文件零运维，校赛/网评规模足够；WAL 支持并发读 |
| DeepSeek | OpenAI 兼容、成本低可高频判题、中文能力强；接入层抽象可切换 GLM/百宝箱 |
| React + shadcn/ui | 快速构建高质量可访问 UI；Recharts 雷达/趋势图成熟 |
| 单容器部署 | Meoo → 阿里云一键部署，公网可访问，评审可实测 |
