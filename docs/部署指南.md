# 部署指南

> AI 能力罗盘 · 部署就绪说明。生产形态 = **单容器**：FastAPI 同源托管前端静态产物（`web/dist`）与 API，无跨域、无第二进程。题库种子（`seeds/questions/`，300 题）在容器启动时经 `python -m app.seed` **幂等导入**（重复启动只做增量比对，不重复建题）。

## 1. 环境变量

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `DEEPSEEK_API_KEY` | 是 | 空（缺失时 LLM 调用直接报错） | DeepSeek 密钥，判题/对话考官/实操窗口/报告建议均依赖 |
| `DEEPSEEK_BASE_URL` | 否 | `https://api.deepseek.com` | 自建网关/代理可覆盖（OpenAI 兼容） |
| `DEEPSEEK_MODEL_JUDGE` / `DEEPSEEK_MODEL_CHAT` | 否 | `deepseek-v4-pro` / `deepseek-flash` | 判题与对话双模型分工 |
| `COMPASS_JWT_SECRET` | 生产必换 | `dev-secret-change-me` | JWT 签名密钥；**保持默认值启动时打 WARNING 日志**，请换 32+ 位随机串 |
| `COMPASS_CORS_ORIGINS` | 否 | `http://localhost:5173` | CORS 白名单，逗号分隔多个来源（单容器同源部署其实不触发跨域，留作前后端分离部署用） |
| `COMPASS_DB` | 否 | `api/compass.db` | SQLite 文件路径（**只认进程环境变量**，docker compose 已设为 `/data/compass.db`） |

本地开发：复制 `api/.env.example` → `api/.env` 并填入 Key；Docker 部署：复制到**仓库根目录 `.env`**（compose 自动读取）。

## 2. Docker 一键部署（推荐）

```bash
cp api/.env.example .env        # 填入 DEEPSEEK_API_KEY，生产同时换 COMPASS_JWT_SECRET
docker compose up -d --build
curl http://localhost:8000/api/health   # {"status":"ok","app":"ai-compass"}
```

- **镜像**（`Dockerfile`，多阶段）：`node:24-slim` 执行 `pnpm build` 产出 `web/dist` → `python:3.13-slim` 安装 `api/requirements.txt`，拷入 `api/app`、`seeds`、`web/dist`；容器启动 `python -m app.seed && uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}`。
- **数据持久化**：`docker-compose.yml` 把 `COMPASS_DB` 指到 `/data/compass.db` 并挂命名卷 `compass-data`，容器重建不丢数据。
- **健康检查**：`GET /api/health`；前端即 `http://localhost:8000`（SPA 深链接由 FastAPI fallback 兜底）。

无 compose 时等价命令：

```bash
docker build -t ai-compass .
docker run -d -p 8000:8000 -e DEEPSEEK_API_KEY=sk-xxx -e COMPASS_JWT_SECRET=换成随机串 -v compass-data:/data -e COMPASS_DB=/data/compass.db ai-compass
```

## 3. 秒悟 Meoo → 阿里云函数计算（公网演示环境）

Meoo 走**镜像部署**（源码上传 → 远程构建 → FC 容器），步骤：

1. `npm install -g @aliyun-meoo/cli && meoo login`
2. 仓库根目录 `meoo projects create "AI 能力罗盘"`（绑定当前目录）
3. 添加两个脚本（远程 Linux 构建环境含 Node 24 / Python 3.13 / pnpm，均在平台基线内）：

   `scripts/setup.sh`（构建：装依赖 + 产前端静态产物）
   ```sh
   #!/bin/sh
   cd /code/web && corepack enable && pnpm install --frozen-lockfile && pnpm build
   cd /code/api && pip install -r requirements.txt
   ```

   `scripts/start.sh`（启动：**必须绑 `0.0.0.0:${PORT:-9000}`**）
   ```sh
   #!/bin/sh
   cd /code/api && python -m app.seed
   exec uvicorn app.main:app --host 0.0.0.0 --port "${PORT:-9000}"
   ```

4. `meoo secrets set DEEPSEEK_API_KEY <真实Key>`、`meoo secrets set COMPASS_JWT_SECRET <随机串>`（密钥不进代码库）
5. 首次 `meoo deploy --runtime image`（此后 runtime 记入 `.meoo/config.json`，直接 `meoo deploy`）
6. 部署完成后平台自动做健康检查（要求非 5xx 真实响应，`/api/health` 即满足），得到公网地址 `https://<id>.meoo.fun`

**如实说明（重要）**：FC 容器实例是**临时的、无持久化本地存储**——SQLite 数据不保证跨实例保留，演示期间平台回收/冷启动后测评记录可能重置（题库种子会随启动重新导入，系统可继续演示）。**正式留存数据请用 §2 的自备服务器 Docker 部署**（compose 卷持久化）。

## 4. 本地验证清单（部署前）

- [ ] `cd api && pytest` 全绿（当前基线 257 通过）
- [ ] `cd web && pnpm build` 成功
- [ ] `uvicorn app.main:app --port 8000` 启动后：注册学员 → 完成一轮测评 → 报告出雷达图（需 `DEEPSEEK_API_KEY` 有效）
- [ ] `COMPASS_JWT_SECRET` 未设置时启动日志出现弱密钥 WARNING（预期行为）；设置后消失
- [ ] 反向代理场景（如有）设置 `COMPASS_CORS_ORIGINS` 为前端实际来源

## 5. 常见问题

| 现象 | 原因与处置 |
| --- | --- |
| 启动日志 WARNING「默认开发密钥」 | 未设 `COMPASS_JWT_SECRET`，生产必须设置后重启 |
| 对话/判题报「缺少 DEEPSEEK_API_KEY」 | 环境变量未注入容器；compose 检查根目录 `.env`，Meoo 用 `meoo secrets set` |
| `database is locked` | SQLite 写锁被长判题事务占用；连接已带 30s busy timeout，高并发再升级 PostgreSQL |
| 跨域请求被拦 | 前端域名不在白名单：`COMPASS_CORS_ORIGINS` 逗号分隔补齐后重启 |
